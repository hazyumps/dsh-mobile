# Plans

One file per issue: `issue-<n>-<slug>.md`, started from `docs/process/PLAN-TEMPLATE.md` by the
planner, as the first commit on the issue's branch (`docs/process/WORKFLOW.md`, step 1).

A plan is the contract for one issue — its acceptance criteria, the tests that pin them, the red
evidence and the verification. It stays in the repo after the merge, so the reasoning behind a
test is findable from `git log` and from the file itself.
